How the race resolves
One row, one winner

Each Yes link carries a unique token. The claim endpoint runs one atomic UPDATE against the pending row, matching on status = 'pending'. Only the first token to arrive flips the row to confirmed and returns success.

Every later Yes tap hits a row that's already claimed and sees the friendly "beat you to it" page. The parent gets a single notification — not one per Yes — and nobody in the group ends up as the awkward runner-up.
